11  Data Preparation

Data Cleaning addressed problems such as missing values, duplicate records, and impossible values. Data preparation is the next step: putting clean data into a form that suits exploratory data analysis (EDA) or a statistical or predictive model. The right preparation depends on what you want to do with the data.

This chapter introduces three common preparation techniques:

  • Binning continuous variables groups numeric values into intervals. In EDA, this helps us summarize and compare groups; here, we compare graduation rates across college spending groups. Binning can also create predictors for a model, but it discards detail and is not always helpful.
  • Scaling numeric variables puts columns on comparable scales. This is especially useful for modeling methods that depend on distances or penalize coefficient sizes, so a variable’s units do not give it disproportionate influence.
  • Encoding categorical variables represents categories with numbers. This is primarily preparation for modeling, because many modeling methods require numeric inputs. The encoding should reflect whether the categories have a meaningful order.

These steps are choices, not requirements for every dataset. Each changes how the data is represented and can affect what an analysis reveals. Choose transformations that serve your question, and check their results before using them.

By the end of this chapter, you should be able to:

  • Explain when binning, scaling, and categorical encoding are useful for EDA or modeling.
  • Create equal-width, equal-count, and custom bins with pd.cut() and pd.qcut(), and check their boundaries and counts.
  • Explain how the choice of bins changes group sizes and hides detail in the original values.
  • Apply min–max scaling and standardization, check the results, and explain which columns are appropriate to scale.
  • Choose and apply binary, ordinal, or one-hot encoding using map() and pd.get_dummies().

11.3 Bin a numeric column

A scatter plot answers the spending question for every college at once, and with 777 noisy points the answer is hard to read:

fig, ax = plt.subplots(figsize=(8, 4.5), layout="constrained")
sns.scatterplot(data=college, x="Expend", y="Grad.Rate", alpha=0.5, ax=ax)
ax.xaxis.set_major_formatter("${x:,.0f}")
ax.set(xlabel="Expenditure per student", ylabel="Graduation rate (%)")
plt.show()

Each college is one point, and Expend alone has hundreds of distinct values. One way to make a comparison like this readable is to bin the column.

11.3.1 What binning is, and why it helps

Data binning groups the values of a numeric column into a few intervals, called bins, and records which bin each value falls into instead of the value itself. Think of it as sorting a long list of numbers into a few labelled jars. Binning simplifies a column so that patterns become visible and comparisons become easy to state.

Why bin? Bins make it easier to describe and compare groups, and to apply a different rule to each group. Federal income tax brackets are a familiar example. Taxable income is split into ranges, and each range is taxed at its own rate. For a single filer in 2024 with a taxable income of $50,000, the first $11,600 is taxed at 10%, the part from $11,600 to $47,150 at 12%, and the last $2,850 at 22%:

The bin edges ($11,600 and $47,150) are not arbitrary: they are thresholds set by tax law, and each bin carries a rule. In the same way, a retailer might classify customers as low, medium, or high spenders, or a college might use tuition bands in a report. The boundaries should serve the question being asked.

Here, binning Expend into low, medium, and high spending lets you compare one summary per group instead of reading a cloud of points. The price is detail: once a college is “medium”, its exact dollar figure is no longer represented in that label. The original Expend column is still available; we store the bin labels in a separate column. That makes the choice of bins, how many and where their edges fall, the important decision. There are three common ways to make it, and the rest of this section works through each:

Method pandas Bins have Suits
Equal-width pd.cut(s, k) The same width, any count Values spread fairly evenly
Equal-count (quantile) pd.qcut(s, k) Approximately equal counts, any width Skewed columns; groups you want to compare
Custom pd.cut(s, bins=[...]) Edges you choose Thresholds that mean something

11.3.2 Equal-width bins with cut()

pd.cut(column, 3) divides the range of a column, from its minimum to its maximum, into 3 intervals of equal width, and returns which interval each value falls into. value_counts(sort=False) lists the intervals in order with their counts:

pd.cut(college["Expend"], 3).value_counts(sort=False)
Expend
(3132.953, 20868.333]     751
(20868.333, 38550.667]     21
(38550.667, 56233.0]        5
Name: count, dtype: int64

Each interval is written (left, right]: the round bracket means the left edge is excluded and the square bracket means the right edge is included, so every value belongs to exactly one bin. (The lowest edge sits slightly below the minimum so that the minimum is included.)

The widths are equal, about $17,700 each, but the counts are not: 751 colleges in the first bin, 21 in the second, and 5 in the third. Expend is strongly right-skewed, as Data Cleaning showed, so a few very high spenders stretch the range and the top two bins cover almost no one. We can give the bins names and check their counts:

width_level = pd.cut(college["Expend"], 3, labels=["Low", "Medium", "High"])
width_level.value_counts(sort=False)
Expend
Low       751
Medium     21
High        5
Name: count, dtype: int64

labels= names the bins in order, from lowest to highest. The labels change how the bins are displayed, but do not change their edges or counts. Always check the counts after binning. Here, almost every college is labelled “Low”, so these bins do little to distinguish spending levels among most colleges.

11.3.3 Equal-count bins with qcut()

pd.qcut(column, 3) does the opposite: it places the edges at the column’s quantiles, so each bin holds roughly the same number of rows. Three equal-count bins are called tertiles. Tied values must stay together, so counts may differ. If ties produce duplicate bin edges, qcut() raises an error; use fewer bins or inspect duplicates="drop" (which reduces the number of bins and requires matching labels).

college["expend_level"] = pd.qcut(college["Expend"], 3, labels=["Low", "Medium", "High"])
college["expend_level"].value_counts(sort=False)
expend_level
Low       259
Medium    259
High      259
Name: count, dtype: int64

Each bin now holds 259 colleges. The edges fall at about $7,334 and $9,682, the 33rd and 67th percentiles. Drawing both sets of edges on the distribution shows the difference between the two methods:

width_edges = np.linspace(college["Expend"].min(), college["Expend"].max(), 4)
count_edges = college["Expend"].quantile([0, 1/3, 2/3, 1])

fig, (ax_width, ax_count) = plt.subplots(1, 2, figsize=(11, 4), sharey=True,
                                         layout="constrained")
for ax, edges, title in [(ax_width, width_edges, "Equal-width bins: cut()"),
                         (ax_count, count_edges, "Equal-count bins: qcut()")]:
    sns.histplot(data=college, x="Expend", bins=40, ax=ax)
    for edge in edges:
        ax.axvline(edge, color="red", linestyle="--")
    ax.xaxis.set_major_formatter("${x:,.0f}")
    ax.set(xlabel="Expenditure per student", title=title)

plt.show()

The red lines are the bin edges. np.linspace(low, high, 4) gives four equally spaced numbers, which are the edges cut() used, and quantile([0, 1/3, 2/3, 1]) gives the edges qcut() used. ax.axvline(x) draws a vertical line at x across the panel.

On the left, the equal-width edges are evenly spaced, so almost every college lands left of the first interior line. On the right, the equal-count edges crowd into the dense part of the distribution, so the bins are narrow where colleges are crowded and wide where they are sparse. The 5 highest spenders no longer get a bin of their own; they are simply part of “High”. Equal-count binning keeps group sizes balanced, but it does not remove extreme values from the original spending column. The “High” label hides a wide range of spending.

Comparing graduation rates across the tertiles, with the mean for each bar:

fig, ax = plt.subplots(figsize=(6, 4), layout="constrained")
sns.barplot(data=college, x="expend_level", y="Grad.Rate", ax=ax)
ax.set(xlabel="Spending per student (tertile)", ylabel="Mean graduation rate (%)")
plt.show()

Graduation rates rise steadily, from 57.3% to 65.9% to 73.0%. As in Data Visualization I, barplot computes the mean of each group for you, and the line on each bar is a 95% confidence interval: none of the three intervals overlap. The pattern the scatter plot hinted at is now easy to read, and each bar is backed by 259 colleges, but the middle group has 258 valid graduation rates because one was marked missing. The mean uses only the nonmissing rates. This is an association: the plot alone does not show that increasing spending would cause a higher graduation rate.

11.3.4 Bins you choose

Sometimes the edges should come from the question rather than from the data: a budget category, a policy threshold, a grading cutoff. Pass cut() a list of edges instead of a number of bins:

edges = [0, 10_000, 20_000, np.inf]
labels = ["Under $10K", "$10K to $20K", "$20K and over"]

budget_level = pd.cut(college["Expend"], bins=edges, labels=labels, right=False)
budget_level.value_counts(sort=False)
Expend
Under $10K       535
$10K to $20K     214
$20K and over     28
Name: count, dtype: int64

Three details make custom bins behave:

  • np.inf is infinity, so the last bin has no upper limit and all finite spending values at or above zero fit within these edges. Any value outside the edges you give would become NaN.
  • right=False closes each interval on the left instead, [left, right), so a college spending exactly $10,000 lands in “$10K to $20K”, which matches how the labels read. Writing 10_000 with an underscore is the same number as 10000, just easier to read.
  • labels= needs one name per bin: three bins from four edges.

These bins answer a budgeting question — how many colleges spend at least $20,000 per student? 28 — at the cost of uneven group sizes, the same trade-off as equal-width bins.

qcut() accepts a list too, but its list holds quantiles rather than values. This splits colleges at the median and the 90th percentile, to set the top 10% of spenders apart:

spending_group = pd.qcut(college["Expend"], [0, 0.5, 0.9, 1],
                         labels=["Bottom half", "50th to 90th percentile", "Top 10%"])
spending_group.value_counts(sort=False)
Expend
Bottom half                389
50th to 90th percentile    310
Top 10%                     78
Name: count, dtype: int64

The list runs from 0 to 1 and the bins hold 50%, 40%, and 10% of the colleges: 389, 310, and 78. Use cut() with a list when the edges are values that mean something, and qcut() with a list when they are shares of the data.

11.4 Rescale numeric columns

Binning turns numeric values into categories. Scaling keeps them numeric but changes their units. It is useful for modeling methods that are sensitive to the scale of their inputs, where larger numerical ranges can otherwise dominate a calculation.

Why scale features?

  • Many algorithms (e.g., k-nearest neighbors, k-means, principal component analysis, gradient descent-based models) compute distances or rely on feature magnitude.
  • Features with larger scales can unduly influence the model if not scaled.

A feature is a column a method uses as an input; in this chapter, it is simply a column. The college columns are measured on very different scales:

scale_cols = ["Apps", "Outstate", "Grad.Rate"]
college[scale_cols].describe().round(1)

Applications, tuition, and graduation rates use different units and ranges. A difference of 100 applications and a difference of 1 percentage point cannot be compared directly by their numerical sizes. Scaling expresses each column on a common scale.

We will keep the original columns and store the scaled versions separately:

11.4.1 Min–max scaling

Min–max scaling expresses a value’s position between the column’s minimum and maximum:

\[x_{\text{scaled}} = \frac{x - \min(x)}{\max(x) - \min(x)}\]

The minimum becomes 0 and the maximum becomes 1. A value halfway between them becomes 0.5. This is what MinMaxScaler did before KNN imputation in Data Cleaning.

minmax = (raw - raw.min()) / (raw.max() - raw.min())
pd.DataFrame({
    "Tuition ($)": raw["Outstate"],
    "Min–max tuition": minmax["Outstate"],
}).head().round(3)
Tuition ($) Min–max tuition
Abilene Christian University 7440 0.263
Adelphi University 12280 0.513
Adrian College 11250 0.460
Agnes Scott College 12960 0.549
Alaska Pacific University 7560 0.270

raw.min() gives one minimum per column, so pandas uses each column’s own minimum and range. The table shows original tuition beside its scaled value: 0.5 would mean halfway between the smallest and largest tuition, not the median or the 50th percentile.

Check that each scaled column has minimum 0 and maximum 1 with minmax.describe().loc[["min", "max"]].

11.4.2 Standardization

Standardization converts each value into a z-score: how many standard deviations it is above or below its column’s mean.

\[z = \frac{x - \bar{x}}{s}\]

A z-score of 0 is at the mean, 1 is one standard deviation above it, and −1 is one standard deviation below it. Unlike min–max scaling, z-scores have no fixed range.

standardized = (raw - raw.mean()) / raw.std()
pd.DataFrame({
    "Tuition ($)": raw["Outstate"],
    "Min–max tuition": minmax["Outstate"],
    "Standardized tuition": standardized["Outstate"],
}).head().round(3)
Tuition ($) Min–max tuition Standardized tuition
Abilene Christian University 7440 0.263 -0.746
Adelphi University 12280 0.513 0.457
Adrian College 11250 0.460 0.201
Agnes Scott College 12960 0.549 0.626
Alaska Pacific University 7560 0.270 -0.716

The two transformations answer different questions: min–max scaling locates tuition within its observed range; standardization locates it relative to its mean and standard deviation. Both preserve the order of values within a column.

Method Formula Result Use when
Min–max (x - x.min()) / (x.max() - x.min()) Every column from 0 to 1 You want values relative to their observed range
Standardization (x - x.mean()) / x.std() Mean 0, SD 1 You want “how unusual” in common units

Check the results. After rounding, the standardized means should be 0 and standard deviations should be 1:

print("Min–max check:")
print(minmax.describe().loc[["min", "max"]].round(3))
print("\nStandardization check:")
print(standardized.describe().loc[["mean", "std"]].round(3))

Small differences from zero can come from floating-point arithmetic. Plotting the columns before and after standardization shows what changed and what stayed the same:

fig, (ax_raw, ax_z) = plt.subplots(1, 2, figsize=(11, 4), layout="constrained")

sns.boxplot(data=raw, ax=ax_raw)
ax_raw.set(title="Original units", ylabel="Value")

sns.boxplot(data=standardized, ax=ax_z)
ax_z.set(title="Standardized", ylabel="Standard deviations from the mean")

plt.show()

Passing a whole DataFrame as data= draws one box per column. On the left, graduation rate is invisible next to applications; on the right, all three are comparable. The shapes have not changed: applications are just as right-skewed after standardizing as before. Rescaling is a linear change of units. To reduce skew you need a transformation such as the log in Data Cleaning.

11.4.3 Checks before scaling

  • Constant columns: if every value is the same, the range and standard deviation are zero. These formulas would divide by zero; set such columns aside.
  • Missing values: pandas skips them when computing the mean, minimum, maximum, and standard deviation, but the missing entries remain missing after scaling.
  • Extreme values: both methods can be affected by outliers. Min–max scaling can squeeze most observations into a small part of the interval. Scaling does not remove outliers or make a skewed distribution symmetric.
Optional: two standard deviation conventions

Pandas uses the sample standard deviation (ddof=1), dividing the squared-deviation sum by \(n-1\). StandardScaler uses ddof=0, dividing by \(n\). Here, \(n\) is the number of nonmissing values in each column. The difference is small for this dataset; use one convention consistently when checking your results.

11.4.4 What not to rescale

For this chapter, rescale columns that measure quantities, such as applications, tuition, or graduation rate. Leave these columns alone:

  • Identifiers, such as a college ID or a ZIP code. They are stored as numbers but work as names, so a scaled ID means nothing.
  • Category labels, such as Private or the spending bin labels. They are not amounts, so they have no mean, minimum, or standard deviation to scale by.
  • Encoded categories, the numeric codes and indicator columns you will create in the next section. Keep them unchanged in these exercises; whether to scale them depends on the modeling method.
  • Constant columns, whose range and standard deviation are zero (see the checks above).

Not every method needs rescaling at all. Rescaling matters for methods that combine columns, through distances as in KNN or through weighted sums. Methods that look at one column at a time, such as the decision trees you will meet in later courses, which split the data at a threshold on a single column, give the same result on raw and rescaled data.

11.5 Encode categories as numbers

The spending levels created earlier are categories, and so is Private. Many modeling methods require numeric inputs. Encoding represents a category with a code or a set of indicators while preserving which category each observation belongs to.

Start by identifying the type of categorical variable:

  • Ordinal: categories have a meaningful order, such as Low, Medium, High.
  • Nominal: categories have no meaningful order, such as Biology, CS, Math.

Both types are discrete. “Nominal” is the term for unordered categories.

11.5.1 Ordered categories: ordinal encoding

The spending tertiles have a meaningful order. Use map() with an explicit dictionary so the codes follow that order:

level_codes = {"Low": 0, "Medium": 1, "High": 2}
college["expend_code"] = college["expend_level"].map(level_codes)
college[["Expend", "expend_level", "expend_code"]].head()
Expend expend_level expend_code
Abilene Christian University 7041 Low 0
Adelphi University 10527 High 2
Adrian College 8735 Medium 1
Agnes Scott College 19016 High 2
Alaska Pacific University 10922 High 2

The codes preserve Low < Medium < High. They are category codes, not dollar amounts. Some models treat 0, 1, and 2 as equally spaced numerical inputs; check whether that assumption suits the model and the question. The codes do not mean that High represents twice the spending of Medium.

Check that every category has a code and that the original and encoded counts match:

print(college["expend_level"].value_counts(sort=False, dropna=False))
print(college["expend_code"].value_counts(sort=False, dropna=False))

11.5.2 Two categories: a single 0/1 indicator

A two-category variable needs only one indicator. For Private, 1 means private and 0 means public. This labels membership; it does not rank one type above the other. map(), introduced in Pandas Intermediate, applies the dictionary to each value:

college["private_code"] = college["Private"].map({"No": 0, "Yes": 1})
college[["Private", "private_code"]].head()

Adelphi University Yes 1
Adrian College Yes 1
Agnes Scott College Yes 1

Check the original and encoded counts, including missing values:

print(college["Private"].value_counts(dropna=False))
print(college["private_code"].value_counts(dropna=False))

There are 565 private colleges (1) and 212 public colleges (0). A category absent from the mapping dictionary would become NaN, so including missing values in the count check helps catch incomplete mappings.

11.5.3 Unordered categories: one-hot encoding

Assigning Biology = 0, CS = 1, and Math = 2 would invent an order. Instead, pd.get_dummies() creates one indicator column per category: 1 for membership and 0 otherwise. This is called one-hot encoding.

majors = pd.Series(["Math", "Biology", "CS", "Math", "CS"], name="major")
pd.get_dummies(majors, dtype=int)
Biology CS Math
0 0 0 1
1 1 0 0
2 0 1 0
3 0 0 1
4 0 1 0

Each row has one 1 and the other entries are 0. dtype=int requests integer indicators. The columns express category membership without imposing an order among majors.

To attach indicators to a DataFrame, give the new columns a prefix and use pd.concat(..., axis=1). This small example keeps the original major beside its indicators:

major_data = pd.DataFrame({"major": majors})
major_dummies = pd.get_dummies(major_data["major"], prefix="major", dtype=int)
major_encoded = pd.concat([major_data, major_dummies], axis=1)
major_encoded
major major_Biology major_CS major_Math
0 Math 0 0 1
1 Biology 1 0 0
2 CS 0 1 0
3 Math 0 0 1
4 CS 0 1 0

Check that the indicator columns sum to 1 in each row with major_dummies.sum(axis=1). This assumes every row has a known, nonmissing category. By default, a missing category produces all zeros; inspect missing values before encoding, or use dummy_na=True when you want a separate missing-value indicator.

11.5.4 Optional: a reference category

With all categories present, each row’s indicators sum to 1. For ordinary linear regression with an intercept, this creates redundant predictors. drop_first=True keeps one fewer indicator. This is a model-specific choice, not a requirement for all one-hot encoding:

pd.get_dummies(majors, prefix="major", dtype=int, drop_first=True)
major_CS major_Math
0 0 1
1 0 0
2 1 0
3 0 1
4 1 0

Here, Biology is the dropped reference category. A row with 0 in both major_CS and major_Math represents Biology. No category information is lost for these complete data; missing values would need separate handling.

Variable Starting choice Example
Ordered categories Ordinal encoding Low → 0, Medium → 1, High → 2
Two categories One 0/1 indicator Public → 0, Private → 1
Unordered categories One-hot encoding Separate indicators for Biology, CS, Math

An alternative for ordered categories: one-hot encoding is also valid when you do not want to impose numeric spacing. It does not explicitly preserve the order, so the model must learn the categories’ relationships. The choice depends on the model.

11.5.5 Encode a whole DataFrame at once

A real dataset usually has several categorical columns, and encoding them one at a time with prefix= and pd.concat() soon gets repetitive. Pass pd.get_dummies() a whole DataFrame instead, and it does every categorical column in one call: each text or category column is replaced by one indicator column per category, named after the source column and the category, and the numeric columns are kept as they are. Three columns of college, one text, one category, and one numeric, show what happens to each:

college_dummies = pd.get_dummies(college[["Private", "expend_level", "Grad.Rate"]], dtype=int)

Each source column’s name is used as the prefix, so prefix= is not needed, and the numeric columns come first with the indicator columns after them. drop_first=True works here too and drops the first category of each encoded column.

Numeric category codes are not automatically recognized as categorical variables. Select columns explicitly with columns=[...] when needed. Check the resulting column names, row count, and missing values after encoding.

11.6 Summary Cheat Sheet

Binning.

Goal Code
Equal-width bins pd.cut(s, 3, labels=["Low", "Medium", "High"])
Equal-count bins (tertiles) pd.qcut(s, 3, labels=[...])
Edges you choose pd.cut(s, bins=[0, 10_000, 20_000, np.inf], labels=[...], right=False)
Quantiles you choose pd.qcut(s, [0, 0.5, 0.9, 1], labels=[...])
See the edges on the distribution ax.axvline(edge) for each edge, over a histogram
Check the counts, in order binned.value_counts(sort=False)

Rescaling.

Goal Code
Min–max to [0, 1] (df - df.min()) / (df.max() - df.min())
Standardize to z-scores (df - df.mean()) / df.std()
Leave unchanged in this chapter category codes and indicators; do not treat identifiers as measurements

Encoding.

Goal Code
Two categories to 0/1 s.map({"No": 0, "Yes": 1})
Ordered categories to codes s.map({"Low": 0, "Medium": 1, "High": 2})
One indicator column per category pd.get_dummies(s, prefix="name", dtype=int)
Drop one as the reference add drop_first=True
Encode every categorical column of a DataFrame pd.get_dummies(df, dtype=int)
Attach new columns pd.concat([df, dummies], axis=1)

The rule to remember: check every preparation step — the bin counts, the rescaled ranges, the encoded values — before you analyse the result.

11.9 Before You Move On

The habit to carry forward is checking each preparation step before you trust it. Binning hides detail and can hide a problem with it, which is why the counts come first. Rescaling changes units and, if applied to the wrong columns, meaning. Encoding replaces words with numbers that carry claims about order and distance. Each check is one line, and each catches a mistake that would otherwise travel silently into every result that follows.

For any dataset you prepare, you should be able to answer five questions:

  1. Why did you bin this column, and why these edges?
  2. How many rows fell into each bin?
  3. What detail is lost when the original values become bin labels?
  4. Which columns did you rescale, and which did you deliberately leave alone?
  5. Which encoding did each categorical column get, and does it imply an order that is not there?

Continue to Data Grouping and Aggregation, where you will learn to use groupby() and aggregation methods such as mean() to summarize data by group.
