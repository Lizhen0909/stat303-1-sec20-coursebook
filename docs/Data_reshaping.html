13  Data Reshaping

Data reshaping changes how values are organized into rows and columns. For example, life expectancy data might have one row per country and year, or one row per country with a separate column for each year. Both layouts contain the same measurements, but they support different tasks: the first makes it easy to plot trends over time, while the second makes it easy to compare years side by side.

This chapter introduces tools for moving between these layouts, distinguishes reshaping from aggregation, and shows how to check the results.

By the end of this chapter you should be able to:

  • Tell long format from wide format, and say which one a task needs: plotting by group, comparing columns side by side, or summarizing.
  • Reshape a grouped result with unstack() and stack(), choose which index level moves with level=, and turn multi-level labels back into ordinary columns.
  • Turn a long table wide with pivot_table() and an explicit aggfunc, and with pivot() when each cell holds exactly one value.
  • Turn a wide table long with melt() (id_vars, var_name, value_name).
  • Check a reshape: count rows before and after, check what each cell combined, and restore column types that reshaping changes.

13.2 Introduction to Data Reshaping

The two layouts differ in where the year values appear:

  • Long format stacks the values into few columns and many rows. Each row is one observation: one country in one year, with its life expectancy.
  • Wide format spreads the values across many columns and few rows. Each row is one unit, such as a country, with one column per year.

Neither format is better in general; the right one depends on what you are about to do.

13.2.1 Why Data Reshaping Matters

  • Different tools need different layouts. Seaborn’s hue= and col=, from the visualization chapters, expect long data: one column holding the group. A comparison of 1957 with 2007 is one subtraction in wide data, where each year is its own column.
  • Some calculations are easy in one layout and awkward in the other. Change over time per country is a column difference when wide; a mean per year is a groupby() when long.
  • Combining datasets requires clear identifiers. A country–year table can be joined to country-level information using country as the key. The next chapter explains how to choose keys and check the resulting matches.

13.2.3 Reshaping Tools in Pandas

Pandas has two pairs of reshaping tools. The first pair works on labels that are already in the index, such as a grouped result; the second works on ordinary columns of a table. The chapter takes them in this order:

Function Direction Works on
unstack() Long → Wide Moves an index level into the column labels
stack() Wide → Long Moves a column level into the index
pivot_table(), pivot() Long → Wide Columns of a long table; pivot_table() summarizes, pivot() only rearranges
melt() Wide → Long Columns of a wide table

To choose among them, start with where the labels you want to move are, then which direction you are going:

13.3 Stacking and Unstacking using stack() and unstack()

The previous chapter grouped life expectancy by continent and year. We start with that result: unstack() moves an index level into the columns, and stack() moves a column level into the index. First watch the year labels move; then we will examine how to choose a level when both axes have multiple levels.

13.3.1 Unstacking (Rows to Columns): unstack()

unstack() turns a long grouped result wide by moving one level of its row index into the columns. Here is the previous chapter’s mean life expectancy per continent and year, a Series whose index has two levels: continent is level 0 and year is level 1 (or -1):

life_by_year = gdp.groupby(["continent", "year"])["lifeExp"].mean()

life_by_year.unstack(level="continent").equals(life_by_year.unstack(level=0))

equals() checks that the objects have matching shapes, labels, and values, with matching data dtypes. Row and column order matter, and missing values in matching positions compare as equal. It is a useful check that these two reshapes agree.

13.3.2 Stacking (Columns to Rows): stack()

stack() is the inverse reshape: it turns a wide table long by moving one level of the column labels down into the row index, and it uses the same level= rules as unstack(). life_wide has a single column level, year, so stacking it sends the years back into the index and returns the original long Series:

life_long = life_wide.stack()
print(life_long.shape)
life_long.equals(life_by_year)
(60,)
True

Together, these examples show the two directions: unstack() moves the year level from the index into the columns, and stack() moves it back. The figure summarizes the round trip using a small slice of the data; the moving year labels are shaded gold.

Levels are numbered from the outside in. The outermost level is 0, the next one is 1, and so on. The innermost level can also be written -1, which is handy because it always means “the innermost” however many levels there are. For country_summary:

get_level_values() lists the labels at one level, which is a quick way to check which level a number refers to. Level 0 of the columns holds the variables, and level -1 holds the statistics:

Levels can also have names. The names attribute shows them. The index levels are named after the columns you grouped by, but the two column levels that agg() created have no names, shown as None:

print(country_summary.index.names)

['continent', 'country']
[None, None]

So level= accepts either form: a name, such as level="continent", when the level has one, or a number, such as level=0, which always works. In this chapter, unnamed column levels are referred to by number.

Finally, because each label is a tuple with one part per level, selecting a single cell takes one tuple for the row and one for the column, from the outermost level inward, just as selecting from a two-level index did in the previous chapter:

country_summary.loc[("Americas", "United States"), ("lifeExp", "mean")]

13.3.4 Back to a Single-Level Table

Multi-level labels are compact for reading but awkward for plotting, filtering, and merging, which expect plain column names. The index part has a tool you already know: reset_index() moves every index level back into an ordinary column. The column part needs one more step: each column label is a pair such as ("lifeExp", "mean"), and joining its two parts with an underscore turns it into one name such as lifeExp_mean.

country_flat = country_summary.reset_index()
country_flat.columns = ["_".join(col).strip("_") for col in country_flat.columns]
country_flat.head()

After reset_index(), the old index columns have an empty second part, ("continent", ""), so strip("_") removes the trailing underscore that joining leaves on them. Joining both parts preserves the variable and the statistic.

13.4 Pivoting from Long to Wide: pivot_table()

unstack() reshapes labels that are already in the index, as in the result of groupby() above. A suitable index can also be created with set_index(). Most long tables, like gdp itself, keep their labels in ordinary columns. pivot_table() turns such a table wide in one call: it groups the rows, summarizes each group with an aggregation function, and spreads the result across columns. This section builds pivot tables with one and two row labels, uses the wide layout for comparisons and a heatmap, and then covers pivot() for tables that need no summarizing.

13.4.1 What is Pivoting?

Pivoting turns long data wide by taking the values of one column and making them the column headers:

  • the unique values of the index= column become the row labels;
  • the unique values of the columns= column become the column labels;
  • each cell holds the values= column, aggregated with aggfunc= over every row that shares that row label and column label.

This is the reshape the diagram in Understanding Wide vs. Long Format showed with pivot() on three countries, plus one step: when several rows share a row label and column label, pivot_table() combines them into one cell. The figure follows the 52 African countries of 1952 into a single cell, and shows what melting that cell gives back:

13.4.2 Example 1: Simple Pivot with Single Index

A table with continents as rows and years as columns, each cell holding the mean life expectancy of that continent’s countries in that year:

    columns="year",      # column labels
    values="lifeExp",    # what goes in the cells
    aggfunc="mean",      # how to combine the rows that share a cell

13.4.4 Practical Use: Temporal Comparisons

With each year in its own column, comparing two years is a matter of putting one column on each axis. The scatter plot below places every country’s 1957 life expectancy against its 2007 value; points above the dashed line y = x improved over the 50 years.

plot_data = life_by_country.reset_index()  # continent back to a column for hue=

plt.figure(figsize=(9, 6))
sns.scatterplot(data=plot_data, x=1957, y=2007, hue="continent", s=60, alpha=0.7)
plt.plot([30, 85], [30, 85], "k--", linewidth=1, label="No change")
plt.xlabel("Life expectancy in 1957")
plt.ylabel("Life expectancy in 2007")
plt.title("50-year change in life expectancy by country")
plt.legend(bbox_to_anchor=(1.02, 1), loc="upper left")
plt.tight_layout()
plt.show()

Almost every country sits above the line. The four below it, where life expectancy was lower in 2007 than in 1957, are all in Africa: Lesotho, Swaziland, Zambia, and Zimbabwe. In the long table this comparison would need the 1957 and 2007 rows of each country matched up first; in the wide table they are already side by side.

A wide table of numbers is also a grid, and sns.heatmap() colours each cell by its value, so patterns across rows and columns are visible at a glance:

plt.figure(figsize=(10, 20))

Reading across a row follows one country over time; reading down a column compares countries within a year. The colours darken from left to right almost everywhere, as life expectancy rose, and the African block at the top stays lightest throughout, with a few rows fading in the later years.

13.4.6 Choosing the Aggregation Function

aggfunc= accepts the same names as agg() in the previous chapter: "mean", "median", "sum", "count", "min", "max", and a lambda for a statistic of your own. If you leave it out, pivot_table() uses the mean. To calculate total population within each continent and year, use "sum"; to calculate the average country population, use "mean". Choose the aggregation to answer your question, and always name aggfunc=. A lambda receives the values of one cell as a Series, so the 90th percentile of life expectancy per continent and year is:

gdp.pivot_table(
    index="continent", columns="year", values="lifeExp",
    aggfunc=lambda x: x.quantile(0.9),
).round(1)

13.4.7 When Each Cell Holds One Value: pivot()

pivot() takes the same index=, columns=, and values= but has no aggfunc: it only rearranges values and never summarizes them. Use it when each row label and column label pair should match exactly one row, as each country and year does here:

gdp_wide = gdp.pivot(index="country", columns="year", values="gdpPercap")
gdp_wide.iloc[:5, :4].round(0)

Angola 3521.0 3828.0 4269.0 5523.0
Argentina 5911.0 6857.0 7133.0 8053.0

What pivot() adds over pivot_table() is a safety check. If two rows share a country and year, pivot() stops with ValueError: Index contains duplicate entries, while pivot_table() would quietly average the duplicates into one cell. Choose pivot() when a duplicate would mean a mistake in the data, and pivot_table() with a named aggfunc= when you intend each cell to summarize several rows.

13.4.8 Check the Keys: Duplicate Observations

Before pivoting, ask whether the proposed row and column labels identify a single observation. The complete Gapminder table has no repeated country–year pairs:

gdp[gdp.duplicated(["country", "year"], keep=False)]
country continent year lifeExp pop gdpPercap

An empty result means the keys are unique. To see what a problem looks like, append one row to toy_long, the three-country table from the start of the chapter, and inspect all rows sharing its key:

toy_duplicate = pd.concat([toy_long, toy_long.iloc[[0]]], ignore_index=True)
toy_duplicate[toy_duplicate.duplicated(["country", "year"], keep=False)]
country year lifeExp
0 USA 2000 76.8
9 USA 2000 76.8

keep=False marks every row in a repeated key, including the first. A pivot() on this table would raise a duplicate-entry error. If the repeated record is an accidental copy, correct it after checking its source. If repeated keys represent legitimate measurements, decide how to summarize them and use an explicit aggfunc. Averaging automatically can hide the difference between these two situations.

13.5 Melting from Wide to Long: melt()

Pivoting turned years into column headers; melt() turns column headers back into values. It moves in the opposite direction to pivoting, following the melt() arrow in Understanding Wide vs. Long Format: it takes a wide table and stacks chosen columns into two new columns, one holding the old column names and one holding the cell values. This section melts the country-by-year table back to long format, uses the long result for a grouped plot, and checks that pivoting and melting form a complete round trip.

13.5.1 Key Parameters

Each parameter names a set of columns, before or after the melt. The figure colours each parameter to match those columns, using the call from Example 1 below:

13.5.2 Why Melt Your Data?

Melting puts the year labels into one column so we can use groupby("year") or seaborn’s x="year". The wide layout remains useful for comparisons between year columns.

13.5.3 Example 1: Basic Melt

melt() works on ordinary columns, so the first step is reset_index(), which turns continent and country from the index of life_by_country back into columns:

life_by_country_flat = life_by_country.reset_index()
life_by_country_flat.iloc[:3, :6]

life_long = life_by_country_flat.melt(
    id_vars=["continent", "country"],  # repeated on every new row

    value_name="lifeExp",              # cell values go here

13.5.5 Pivot ↔︎ Melt: The Full Circle

For this complete country–year grid, pivoting and melting can recover the selected data. A round trip checks that the values and identifiers survived. life_long came from gdp by pivoting wide and melting back, so after sorting both the same way and keeping the same columns, the two tables should be identical:

cols = ["continent", "country", "year", "lifeExp"]
original = gdp[cols].sort_values(cols[:3]).reset_index(drop=True)
round_trip = life_long[cols].sort_values(cols[:3]).reset_index(drop=True)
round_trip.equals(original)
True

True: every row, value, and type matches. Without the astype(int) step above, the same check returns False, because the year column would have object dtype in one table and integer dtype in the other, even though its values are integers in both.

The round trip works because each cell of life_by_country held exactly one country’s value. When pivot_table() averages several rows into a cell, as in the figure at the start of the pivoting section, melt() returns those averages, not the rows behind them, so no reshape can recover the original table.

The round trip also needs a complete grid. Melting toy_incomplete_wide, the wide table from the pivoting section with Canada’s 2005 observation removed, includes its empty cell:

toy_incomplete_long = toy_incomplete_wide.reset_index().melt(
    id_vars="country", var_name="year", value_name="lifeExp"
)
print("Original rows:", len(toy_incomplete))
print("Rows after pivot and melt:", len(toy_incomplete_long))
toy_incomplete_long[toy_incomplete_long["lifeExp"].isna()]
Original rows: 8
Rows after pivot and melt: 9
country year lifeExp
3 Canada 2005 NaN

Eight input rows became nine rows after the round trip. Melting creates one row for every selected cell, including cells containing missing values. Here we know the extra row represents an absent observation. In other data, a NaN might belong to an observed record with a missing measurement. Do not automatically drop all missing values to force the row count to match: retain the original keys when that distinction matters.

The rule to remember: after every reshape, check the number of rows, what each cell combined, and the column types, and name aggfunc= whenever a cell summarizes several rows.
