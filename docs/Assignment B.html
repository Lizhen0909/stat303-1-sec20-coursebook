Appendix B — Reproducible Project Setup Assignment

Assignment B

Instructions

  1. Complete this assignment after Chapters 1–2 and their practice activities. It is worth 100 points. See Canvas for the due date.

  2. You may discuss approaches with classmates, but write your own code and explanations and record evidence from your own computer. Put Python computations in Code cells and explanations and copied terminal evidence in Markdown cells.

  3. Download the Assignment B project kit. Extract it and open stat303-assignment-b with File → Open Folder in VS Code. Work in the supplied assignment_b.ipynb. This is a new project, separate from the chapter practice folder.

  4. This page contains the complete assignment instructions. The starter notebook contains numbered answer spaces and supplied demonstration code. Keep those sections in order and answer every numbered part below.

  5. Submit one file, assignment_b.html, to the Assignment B submission in Canvas. Keep the notebook, data, and requirements.txt locally. Do not submit your .venv folder or the ZIP. You may replace your personal username in copied paths with [username], retaining enough detail to identify the project and environment.

  6. The data are fictional library-branch visit counts for one illustrative day. Pandas and plotting code are supplied in the notebook; you are assessing and explaining the workflow, not being asked to write unfamiliar analysis code.

  7. Generative AI. You may use generative AI tools (ChatGPT, Claude, GitHub Copilot, and similar) to understand concepts, interpret error messages, and debug code you have written. You may not use them to produce the code or written answers you submit. The test: you should be able to explain every line you submit and reproduce it without assistance. Disclose any use in a short note at the end of your submission. Honest disclosure carries no penalty on its own; undisclosed use is an academic integrity violation under the course syllabus.

The extracted kit starts with:

stat303-assignment-b/
├── assignment_b.ipynb
├── data/
│   └── library_visits.csv
└── README.md

You will create this project’s own .venv/ and requirements.txt. Use the Chapter 1 Quarto refresher and Chapter 2 environment instructions as references. The Quarto VS Code extension is optional; the Quarto application performs rendering.

1. Organize the Project and Explain the Tools (10 points)

1.1 Project evidence (4 points)

Open the extracted assignment folder and add your name to the notebook. In the terminal, show the current directory and list its contents. Copy the commands and relevant output into your answer, demonstrating that assignment_b.ipynb and data are in the project folder.

Credit: project location and listing evidence, 3 points; name, 1 point.

1.2 Tool roles (6 points)

In your own words, explain the role of each of these five tools in completing this assignment: VS Code, the Jupyter notebook, its Python kernel, the terminal, and Quarto. Then explain why a visible saved output does not by itself prove that the current notebook runs correctly.

Credit: five tool roles, 1 point each; saved-output explanation, 1 point.

2. Create and Verify a Project Environment (25 points)

2.1 A separate environment (8 points)

Create or identify a .venv inside stat303-assignment-b, using an existing appropriate Python installation. Do not copy the practice project’s .venv. Record which existing Python you used to create it and the creation method (VS Code or terminal). Explain why this assignment gets its own environment and how that helps when two projects need different package versions.

Credit: creation method and source Python, 4 points; isolation explanation, 4 points.

2.2 Check before installing (7 points)

Activate the environment using the command for your shell, or use Chapter 2’s direct-executable method. Before installing packages, answer the three questions: Where am I typing? Which Python am I using? Which folder is current?

Record your shell, the activation command or direct-executable method, and the commands and outputs identifying the Python executable and current directory. Explain which part of the Python path identifies this assignment’s .venv.

Credit: method and shell, 2 points; three answers, 3 points; executable-path interpretation, 2 points.

2.3 Connect the notebook (10 points)

After installing the required packages in Question 3, select the assignment’s .venv as the notebook kernel. In a notebook code cell, display the Python version, executable path, and current working directory. Compare the notebook executable with the terminal executable and explain how you know both refer to this assignment’s environment. Explain why choosing a workspace interpreter alone is not sufficient to verify the notebook kernel.

Credit: notebook output, 4 points; comparison and evidence, 4 points; interpreter/kernel distinction, 2 points.

3. Install and Verify Packages (15 points)

3.1 Terminal installation (5 points)

Use the VS Code terminal to install ipykernel, numpy, pandas, and matplotlib into the assignment environment. Record the command and explain why python -m pip (or the verified full Python executable followed by -m pip) targets the intended environment.

3.2 Notebook installation (4 points)

After selecting the assignment kernel, install Seaborn with %pip in a temporary notebook code cell. Record the command and explain which environment it targets. Restart the kernel if needed, then remove the temporary installation cell so a fresh run does not reinstall packages. Keep the command in Markdown.

3.3 Verify the imports (6 points)

In a code cell, import NumPy, Pandas, Matplotlib, and Seaborn and print their version numbers. Explain your first diagnostic step if an installation succeeds in the terminal but the notebook cannot import the package.

Credit: four successful imports/version outputs, 4 points; diagnosis, 2 points. Package versions may differ across computers.

4. Navigate Folders and Locate the Data (20 points)

4.1 Compare two working directories (8 points)

Record the notebook’s current directory. In the terminal, enter data, show the terminal’s directory, and list the CSV file. While the terminal is still inside data, check the notebook directory again. Record the evidence and explain why the two processes can have different current directories. Return the terminal to the project root and verify it.

Credit: navigation and CSV listing, 3 points; simultaneous directory comparison and explanation, 3 points; verified return, 2 points.

4.2 Construct and verify a path (8 points)

Use pathlib in the notebook to construct the relative path to data/library_visits.csv. Display its resolved path and confirm that it is a file before reading it. Explain what the relative path is relative to, and distinguish it from the displayed absolute path.

Credit: path construction, resolved path, and successful file check, 5 points; explanation, 3 points.

4.3 Reason about a different starting folder (4 points)

Suppose a notebook process had stat303-assignment-b/notebooks as its current working directory, with data still in the project root. Write the relative Path expression that would reach library_visits.csv and explain the role of ... This is a written hypothetical question; do not move the supplied notebook or create an extra folder.

5. Record Dependencies and Diagnose a Problem (15 points)

5.1 Requirements record (8 points)

With the terminal back in the project root and using the assignment Python, export requirements.txt. Record the command and where the file was created. Open it, copy two actual package/version entries into Markdown, and explain what the file records. State one reason it does not guarantee identical behavior on every computer. Your Python version is already recorded in Question 2.

Credit: export command and location, 3 points; two entries and interpretation, 3 points; limitation, 2 points.

5.2 Diagnose an incorrect filename (7 points)

Create a separate path for an intentionally nonexistent filename in data. Predict the result of .is_file(), run the check, and explain the observed result. Describe how you would diagnose this result if you expected the file to exist, then demonstrate that the original correct path still returns True. Do not rename/delete data or deliberately leave an exception in the notebook.

Credit: prediction and false check, 2 points; diagnosis, 3 points; correct-path verification, 2 points.

6. Run and Interpret the Supplied Analysis (10 points)

Run the supplied data-reading and plotting cells. They display the six records, calculate the mean number of visits, and create a labeled bar chart. Keep their output in your report.

6.1 Verify the result (4 points)

Report the number of records and mean visits shown by the supplied code. Check that the table and plot use the same branch identifiers.

6.2 Interpret the figure (6 points)

Explain what each axis represents and identify the branch with the most visits and the branch with the fewest. Explain why these fictional counts for one day do not establish a general pattern for real libraries.

Credit: axes, 2 points; largest and smallest branches, 2 points; limitation, 2 points. You do not need to rewrite the Pandas or plotting code.

7. Prepare the HTML Submission (5 points)

Restart the selected kernel, run all cells in order, resolve unexpected errors, and save. Record a brief fresh-run verification note. From the assignment project folder, render with:

quarto render assignment_b.ipynb --to html

Open assignment_b.html, then copy the HTML alone into another folder and open that copy. Check that your explanations, code, table, and plot are visible. Add a short verification statement to the notebook, save, and render again so it appears in the final report. Upload the final HTML to Assignment B in Canvas.

Formatting points follow the existing assignment style:

  • A Quarto-rendered HTML file that opens with its table, plot, and final verification note (2 points).
  • Relevant, concise output without unnecessary installation logs or large extraneous printouts (1 point).
  • Final written answers in Markdown (1 point).
  • No unnecessary/redundant code or text; required code runs in order (1 point).
